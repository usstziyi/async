## 核心答案

**是的，协程的执行完全依赖外部推动，它自己是不会跑的。**

这个"推手"就是**事件循环（Event Loop）**，通常被称为调度器或驱动器。

---

## 一、协程的"惰性"本质

先看一个反直觉的现象：

```python
import asyncio

async def hello():
    print("Hello")
    await asyncio.sleep(1)
    print("World")

# 只是创建协程对象
coro = hello()
print("协程已创建")  # 会立即打印

# 什么都不做，等3秒
import time
time.sleep(3)

# 结果：整个程序结束，"Hello" 永远不会被打印！
```

**输出：**
```
协程已创建
```

`hello()` 函数体内的代码**一行都没有执行**。没有外部推动，协程就是一段"冻结的代码"，只是一个对象躺在内存里。

## 二、推动协程的三种方式

### 方式1：手动驱动（教学演示）

```python
async def hello():
    print("Hello")
    await asyncio.sleep(1)  # 第1个暂停点
    print("World")
    return "Done"

coro = hello()
gen = coro.__await__()

# 第1次推动：启动协程
future = gen.send(None)  # 打印 "Hello"，返回一个 Future 对象
print(f"协程暂停在 await，交出控制权，给了我们一个 {type(future).__name__}")

# 模拟等待1秒
import time
time.sleep(1)

# 第2次推动：继续执行
try:
    gen.send(None)  # 打印 "World"，然后抛 StopIteration
except StopIteration as e:
    print(f"协程完成，返回值: {e.value}")
```

**关键点：每次 `send` 就是一次推动，没有 `send` 协程就永远停在原地。**

### 方式2：`asyncio.run()` 自动驱动（日常使用）

```python
import asyncio

async def main():
    print("开始")
    await asyncio.sleep(1)
    print("结束")

# asyncio.run 内部会启动事件循环，自动反复推动协程
asyncio.run(main())
```

**`asyncio.run()` 做了什么？**
1. 创建一个事件循环
2. 把协程包成 Task
3. 反复调用 `send()` 推动协程
4. 遇到 `await` 时，检查等待的 I/O 是否就绪
5. 就绪后再次 `send()` 恢复执行
6. 协程结束，关闭循环

### 方式3：`await` 嵌套驱动（协程间接力）

```python
import asyncio

async def inner():
    print("inner 开始")
    await asyncio.sleep(0.5)
    print("inner 结束")
    return "内层结果"

async def outer():
    print("outer 开始")
    result = await inner()  # 这里的 await 会驱动 inner 协程
    print(f"outer 拿到: {result}")

asyncio.run(outer())
```

**输出：**
```
outer 开始
inner 开始
inner 结束
outer 拿到: 内层结果
```

当 `outer` 执行到 `await inner()` 时：
- `outer` 暂停
- 事件循环接管，开始推动 `inner`
- `inner` 完成后，事件循环把结果送回 `outer`
- `outer` 恢复执行

## 三、事件循环如何"推动"协程？

以一个真实的 I/O 场景为例：

```python
import asyncio

async def fetch_data():
    print("开始网络请求")
    await asyncio.sleep(2)  # 模拟耗时 I/O
    print("数据到了")
    return "数据"

async def main():
    task = asyncio.create_task(fetch_data())
    print("协程已提交给事件循环")
    result = await task
    print(f"拿到结果: {result}")

asyncio.run(main())
```

**事件循环的推动过程：**

```python
# 事件循环内部大致是这样运转的：

# 1. 创建 Task，底层拿到生成器
gen = fetch_data().__await__()

# 2. 第一次推动：启动协程
future = gen.send(None)  # 打印"开始网络请求"，返回一个 Timer 相关的 Future

# 3. 检查这个 Future 是否完成
if not future.done():
    # 没完成，把协程挂起，注册回调
    future.add_done_callback(lambda f: resume_coro(f))

# 4. 事件循环去处理其他任务...

# 5. 2秒后，Future 完成，回调触发
def resume_coro(future):
    # 6. 第二次推动：恢复协程
    gen.send(None)  # 打印"数据到了"
```

## 四、协程的三种状态

```python
import asyncio
from inspect import getcoroutinestate

async def demo():
    await asyncio.sleep(1)

coro = demo()
print(getcoroutinestate(coro))  # CORO_CREATED（已创建，未启动）

# 手动推动一步
gen = coro.__await__()
gen.send(None)  # 启动后暂停在 await
print(getcoroutinestate(coro))  # CORO_SUSPENDED（已暂停，等待推动）

# 继续推动
try:
    gen.send(None)  # 完成
except StopIteration:
    pass
print(getcoroutinestate(coro))  # CORO_CLOSED（已关闭，无法再推动）
```

**状态流转：**
```
CORO_CREATED（创建） 
    ↓ 第一次 send/next 推动
CORO_SUSPENDED（暂停） 
    ↓ 再次 send/next 推动
CORO_SUSPENDED（可能多次暂停） 
    ↓ 最后一次 send/next 推动
CORO_CLOSED（关闭）
```

## 五、为什么不设计成自动执行？

这涉及到协程的核心优势：**协作式多任务**。

```python
async def task1():
    for i in range(3):
        print(f"task1 - {i}")
        await asyncio.sleep(0.1)  # 主动让出控制权

async def task2():
    for i in range(3):
        print(f"task2 - {i}")
        await asyncio.sleep(0.1)  # 主动让出控制权

async def main():
    await asyncio.gather(task1(), task2())

asyncio.run(main())
```

**输出：**
```
task1 - 0
task2 - 0
task1 - 1
task2 - 1
task1 - 2
task2 - 2
```

两个协程交替执行，每个 `await` 都是"让出控制权"的信号，告诉事件循环："我暂时没事了，你去推动别人吧"。

如果协程自动执行到底，就没法实现这种协作式切换了。

---

## 六、一句话总结

> **协程是"被动"的，事件循环是"主动"的。**
> 
> 协程通过 `await` 主动暂停并交出控制权，事件循环负责在合适的时机用 `send()` 推动它继续执行。
> 
> 没有事件循环这个"推手"，协程只是一段永远不会执行的死代码。
